1. Pendahuluan

Sistem deteksi kebakaran dini dan respons otomatis (misalnya aktifkan pompa) penting untuk mengurangi risiko kerugian. Dengan Internet of Things (IoT), sensor dan aktuator di lapangan dapat dipantau dari jarak jauh. Proyek ini menghubungkan ESP32 sebagai node lapangan, Supabase sebagai basis data dan saluran realtime, serta aplikasi web Next.js yang di-deploy di Vercel.

Laporan menjelaskan komponen apa saja yang dipakai, alur data dari sensor hingga browser, dan cara kode dijalankan pada firmware maupun frontend.

2. Rumusan masalah dan tujuan

Rumusan masalah

  • Bagaimana data sensor/aktuator terlihat realtime di dashboard?
  • Bagaimana satu basis data aman untuk embedded dan browser?
  • Bagaimana reset WiFi ESP dapat diminta dari tanpa kabel UART?

Tujuan

  1. Merancang firmware ESP32 dengan filter sensor dan kendali servo, relay, alarm.
  2. Mengintegrasikan penyimpanan & realtime dengan Supabase.
  3. Membangun antarmuka Next.js yang bereaksi terhadap perubahan data.
  4. Mendokumentasikan arsitektur untuk akademik / pemeliharaan.

4. Arsitektur sistem

Seluruh komunikasi melewati Supabase. ESP tidak memanggil domain Vercel; browser dan ESP sama-sama memakai URL & kunci project Supabase.

5. Alur data (end-to-end)

Urutan pesan saat log masuk dan saat kontrol/reset WiFi lewat tabel control:

  1. ESP POST JSON ke /rest/v1/fire_logs.
  2. Baris tersimpan; Realtime mendorong ke klien yang berlangganan.
  3. Browser memperbarui state UI (sudut, api, relay, log).
  4. Untuk reset WiFi: UI PATCH control; ESP GET periodik memeriksa wifi_reset.

6. Cara kode berjalan — firmware ESP32

Berkas: esp32_fire_system.ino.

setup()

  • Inisialisasi pin, servo (kalibrasi PWM), posisi awal tengah.
  • WiFiManager membuka hotspot konfigurasi (mis. SSID FIRE_SYSTEM_FIKRI) bila perlu.

loop()

  • Reconnect WiFi jika putus (periodik).
  • Baca sensor + filter threshold.
  • Mode api: relay ON, alarm terjadwal, nozzle ikut sudut; mode aman: relay OFF, servo scan simetris dengan pembatasan frekuensi tulis PWM.
  • POST fire_logs pada interval.
  • Poll wifi_reset pada control.
  • yield() + delay kecil agar stack WiFi stabil.

8. Cara kode berjalan — dashboard (Next.js)

Berkas utama: app/page.tsx (client component).

  • Saat mount: fetch baris terbaru fire_logs, fetch log terkini, subscribe Realtime.
  • Interaksi: toggle/slider memanggil PATCH ke control?id=eq.1; tombol reset mengirim wifi_reset.
  • Status "perangkat online" memakai usia created_at data terakhir (bukan ping WiFi langsung).

10. Basis data Supabase

  • fire_logs: histori pengukuran (flame, relay, angle, created_at, dll.).
  • control: biasanya satu baris (id=1) untuk perintah UI, termasuk wifi_reset.
  • RLS: policy harus mengizinkan operasi yang dipakai kunci anon sesuai kebijakan Anda.

12. Kesimpulan & saran

Sistem mengintegrasikan ESP32, Supabase, dan Next.js melalui pola pusat data tunggal. Firmware bekerja dalam loop waktu-nyata dengan tugas jaringan terjadwal; aplikasi web reaktif terhadap peristiwa basis data.

Saran: kolom device_id untuk multi-board; firmware membaca control agar kontrol web sama dengan hardware; autentikasi untuk produksi.
